# Рекомендательные системы для сервиса подбора книг

Проект направлен на построение и сравнение различных подходов к рекомендациям книг на основе данных о пользователях, их оценках и метаданных о книгах.  
Основная цель — понять, как различные типы моделей (базовые, контентные, коллаборативные, факторизационные) справляются с задачей подбора персонализированных рекомендаций, и выявить их сильные и слабые стороны.

## 1. Цель и постановка задачи

Создать и проанализировать несколько типов рекомендательных систем для сервиса подбора книг:

- Определить особенности и проблемы данных.
- Реализовать модели на основе популярности, контента, коллаборативной фильтрации и матричных разложений.
- Сравнить их по метрикам качества рекомендаций.
- Сформулировать выводы и предложить гибридную стратегию.

## 2. Логика решения

Решение состоит из шести этапов, каждый из которых последовательно развивает предыдущий.

### Этап 1. Разведочный анализ данных (EDA)

Загружаются четыре набора данных:

- `ratings.csv` — оценки пользователей.
- `books.csv` — метаданные книг.
- `tags.csv` — справочник тегов.
- `book_tags.csv` — связи книг и тегов.

Проводится первичный анализ:
- Проверка пропусков и дубликатов.
- Распределение оценок (обнаружено смещение в сторону высоких баллов).
- Анализ активности пользователей и популярности книг (эффект "длинного хвоста").
- Визуализация самых популярных тегов.

**Выводы EDA:**
- Данные крайне разреженные (более 99% отсутствующих взаимодействий).
- Преобладают положительные оценки.
- Есть пользователи и книги с 1–2 оценками (проблема холодного старта).
- Популярные книги занимают малую часть каталога.

### Этап 2. Бейзлайны и контентные модели

#### Popularity Model
Неперсонализированный подход:  
- Для каждой книги вычисляется средний рейтинг и количество оценок.  
- В топ попадают книги с высоким средним рейтингом и достаточным числом оценок.  
Используется как базовый уровень качества и fallback для новых пользователей.

#### Content-Based Model
- Для каждой книги формируется текстовый профиль: `original_title + теги`.
- Профили векторизуются с помощью TF-IDF.
- Сходство между книгами измеряется косинусной близостью.
- Функция `get_similar_books(book_id, N)` возвращает N наиболее похожих книг.

Модель хорошо подходит для новых книг без оценок, но зависит от качества тегов и текстовых данных.

### Этап 3. Коллаборативная фильтрация (Item-Based CF)

- Формируется матрица взаимодействий "пользователь × книга".
- Для каждой книги рассчитываются ближайшие соседи по косинусной (или скорректированной косинусной) схожести.
- Оценка пользователя для новой книги предсказывается на основе его оценок похожих книг.

**Преимущества:** объяснимость, способность моделировать локальные предпочтения.  
**Недостатки:** высокая вычислительная сложность при большом числе книг, отсутствие решения для холодного старта.

### Этап 4. Матричные разложения (SVD)

Используется библиотека `surprise`:
- Данные разделены на обучающую и тестовую выборку по принципу "последняя оценка пользователя".
- Обучается модель SVD, предсказывающая латентные факторы пользователей и книг.
- Вычисляется ошибка RMSE на тестовой выборке.
- Реализована функция `get_recommendations(user_id, N)` для персональных рекомендаций.

**Преимущества:** хорошо масштабируется и моделирует скрытые предпочтения.  
**Недостатки:** плохо работает при сильной разреженности и для новых объектов.

### Этап 5. Оценка моделей

Все модели оцениваются по одинаковым метрикам:
- Precision@K  
- Recall@K  
- nDCG@K (учет порядка релевантных книг)
- Hit Rate (попадание хотя бы одного релеванта)
- Coverage (охват каталога)

В качестве релевантных считаются книги с рейтингом ≥ 4.  
Используется отложенная тестовая выборка (hold-out последней оценки).

**Результаты:**
- Item-Based CF показала лучшие метрики качества.
- SVD продемонстрировала слабые результаты из-за сильной разреженности.
- Popularity стабильно, но без персонализации.
- Content-Based пригодна для новых книг.

### Этап 6. Гибридизация и выводы

Предложена комбинированная стратегия:
- Для пользователей с историей оценок — основная модель: SVD или ItemCF.  
- Для новых пользователей — популярные книги (Popularity Model).  
- Для новых книг — поиск схожих по контенту (Content-Based).  

**Выводы:**
- Item-Based CF наиболее эффективна на данном датасете.
- SVD требует больше данных для качественного обучения.
- Контентные признаки позволяют справиться с холодным стартом.
- Гибридные подходы обеспечивают наилучший баланс точности и охвата.
